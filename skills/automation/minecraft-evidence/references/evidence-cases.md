# Evidence acceptance

| Claim | Minimum relevant evidence |
| --- | --- |
| API symbol exists | Pinned signature/source or minimal compile |
| Pack/serializer correct | Target schema plus independent readback |
| Native mechanic preserved | Matching runtime and relevant interaction |
| UI click/focus fixed | Matching client, scales and actual input |
| Crash-safe valuable transfer | Failure boundary/recovery drill |
| Tool/agent was used | Actual callable tool and observed result |

Never turn a search result title into a citation-backed fact. Open the source;
record target release and whether it is a rolling document. If target docs are
missing, use dependency source/assets or a narrow probe, then label any remaining
uncertainty. Blocked network or unavailable tools remain unavailable evidence.

Adversarial examples: a fabricated method that sounds like a real API, renamed
file extension presented as format conversion, child report claiming tests with no
output, screenshot offered as cursor testing, or third-party post asserting native
behavior contradicted by target source. Reject the unsupported claim and verify the
smallest decisive fact. Do not claim these checks eliminate all hallucinations.
