# Minecraft task routing

Identify outcome, edition, exact release, runtime/loader and client requirements from actual artifacts. Preserve scope without imposing a genre, palette, language, currency or deployment path.

- Start with $minecraft-version-compatibility if platform support is unclear. For broad gameplay use $minecraft-gameplay-design and only relevant mechanics; unknown custom rules require research.
- Apply $minecraft-evidence to material compatibility/API claims and honest verification. Do not invent unavailable tools, source findings or test results.
- Use $minecraft-coworker for shared work/handoffs. Use $minecraft-subagents only for already-authorized delegation when supported; this router does not authorize spawning.
- Read references/routing.md when selecting specialized domains. Discover skill names rather than relying on sibling paths next to a global junction.
- Keep one owner for live items, objectives, groups and world state. Existing native features/services come first; skills do not expand permission for live changes.

## Verification

Verify the selected platform supports the requested feature and choose checks that cover server behavior, client presentation or recovery as applicable.

## Example request

Plan a survival extension, creative editor or arena game using only relevant mechanics and verified target APIs.
